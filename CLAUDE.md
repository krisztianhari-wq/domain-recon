# domain-recon – fejlesztői jegyzet

Domain-feltérképező: aldomének (CT + passzív források) → DNS → (aktív) portscan, ujjlenyomat, kitettség, PQ-TLS; lista, gráf, exportok. Felhasználói leírás (angol): README.md; biztonsági audit: AUDIT.md. Üzemeltetési részletek: CLAUDE.local.md (nincs gitben).

**Ez a repó PUBLIKUS.** Ide és a README/AUDIT-ba nem kerülhet szerver-IP, saját hosztnév/infra-részlet, személyes név/e-mail, belső céges információ vagy konkrét (harmadik fél) célpont. A README és az AUDIT angol, infra-információ nélkül.

## Indítás és teszt
- Venv: `/opt/homebrew/bin/python3.14 -m venv .venv && .venv/bin/pip install -r requirements.txt` (a rögzített FastAPI/uvicorn 3.10+ kell, a rendszer-python 3.9 nem jó).
- Launch config `domain-recon` (projekt `.claude/launch.json` és a közös `~/Claude_code/.claude/launch.json`) → 127.0.0.1:8795.
- CLI: `.venv/bin/python -m app.cli scan <domain> [--active] [--ports service|common|full|custom --custom 22,80,8000-8100] [--intensity polite|normal|aggressive] [--brute] [--no-ports] [--private] [--json]` (alapból csak passzív).
- Teszt: nincs unit-teszt; a CI `check` jobja: `python -m compileall -q app`, import-smoke (`app.main, app.engine, …`), `python -m app.cli scan --help`. Helyben ugyanezt futtasd.
- Függőségek rögzítve; `pip-audit -r requirements.txt` (tiszta), bandit magas 0.

## Felépítés
- `app/engine.py` Engine: enumerate → resolve → scan, intenzitás-profilok, megszakítás. `sources.py` certspotter/crt.sh/anubis/wayback/hackertarget; `enrich.py` PTR + ASN/ország/org (Team Cymru DNS); `ports.py` (service / common ≈1075 / full 65535 / custom); `fingerprint.py` HTTP/TLS/banner + tech; `vulncheck.py` GET-only kitettség (.git/.env/dir-listing/ES/Kibana/actuator…); `pqscan.py` poszt-kvantum TLS; `netchecks.py` DNS/TCP (a saját uptime-monitorból másolva); `db.py` SQLite WAL (`_migrate()` ALTER-rel pótolja a hiányzó oszlopokat); `report.py` MD/JSON/CSV, `xlsx.py`; `main.py` API; `desktop.py` + `launcher.py` asztali indító.
- Háromfázisú, mindegyik külön indítható: PASSZÍV az alap (wildcard-felismerés, DNS-posture MX/NS/CAA/SPF/DMARC/DKIM, takeover-heurisztika); AKTÍV `POST /api/scan/{id}/active` (portscan, ujjlenyomat, PQ-TLS, kitettség); **CVE** `POST /api/scan/{id}/cve` — önálló, könnyű HTTP-fejléc-lekérés az élő hostokon → termék+verzió → ismert kritikus CVE (`vulncheck.php_cve_findings`, jelenleg php2shell CVE-2026-109618/109619, verzió alapján, nem kihasználás). Gráf: `/graph` (SVG domain↔host↔IP↔ASN).
- **Kitett eszközök fázis (AI / low-code / monitoring, v0.10.0):** önálló, CVE-mintájú fázis, saját gombbal — `POST /api/scan/{id}/svc` → `engine.run_svc()` → `app/probe_services.py probe_host()`. Az élő hostokon kíméletes GET-ekkel azonosítja: **Ollama** (verzió, nyílt `/api/tags`, CVE-2024-37032), **Open WebUI** (`/api/config` verzió + nyitott signup/auth-off), **Flowise** (verzió, auth nélküli felület, CVE-2024-31621), **Langflow** (`/api/v1/version`, CVE-2025-3248 unauth RCE), **n8n** (`/rest/settings` versionCli + showSetup), **Grafana** (`/api/health` verzió, CVE-2021-43798), **Cacti** (verzió, <1.2.27; csak 200-as, valódi Cacti-oldal — az átirányító „Redirecting to /cacti” nem találat, v0.10.1), **Zabbix/Netdata/Prometheus/Portainer** (elérhetőség+verzió). Reverse proxy mögötti (80/443) ÉS közvetlen IP:port (default portok: 11434/19999/9090/9000/7860/5678/3000/8080) telepítést is néz. GET-only, NEM kihasználás; verzió→CVE a modulban. Finding `h.svc` (shape mint a cve/vuln + `product`/`version`/`cve`), súlyosság: elérhető→info/low, auth nélkül/nyitott→high, sebezhető verzió→CVE-súly. DB: `svc_status/svc_stage/svc_done/svc_total` (migráció). UI: `#svccard` + `#svcgo` gomb, `svc` szűrőcsempe/pill, badge+részlet-blokk; riport (HTML/PDF/MD/JSON/CSV) is tartalmazza (`report svc_tools`, `_host_clean exposed_tools`). A verzió→CVE tábla karbantartandó (mint a php2shell).
- `static/`: sadrobot UI, HU/EN (`i18n.js`, hover-magyarázatok EXPLAIN), `theme.js`; index/graph HTML `no-cache`. **Modern-dizajn (v0.9.3):** a felület Krisz `modern-dizajn` (Minimal Enterprise) stílusában van — `modern.css` + `modern.js` + saját hosztolt Inter (`fonts/`), `sadrobot-icon.png`. **Keret NÉLKÜL** (egyfolyamatú eszköz): nincs `has-shell`/bal/alsó menü, csak `header.top` (sadrobot logó + HU/EN + téma) + `main.content` + sadrobot `.footer`. A statisztika KPI-csempe (`.kpi .v/.l`, a kattintó `data-f` megmaradt). A régi token-nevek (`--bg/--panel/--accent`) aliasként megvannak (a gráf miatt); a `graph.html` `.brand`→`.rbrand`. A `.hide` továbbra is `display:none`. Alap téma világos (sötét mentésre/rendszerre). CSP: `script-src 'self'` → nincs inline script, a `modern.js`/`app.js` külső.
- „Jelentés" = `/report?id=` (`report.py build_html` + `report.css` A4). **PDF: egykattintásos szerveroldali letöltés** (`/api/export/{id}.pdf?lang=&focus=&cve=`, `report.py build_pdf`, reportlab) — nem a böngésző nyomtatásán múlik (a korábbi „üres PDF" ezzel megszűnt); a „Nyomtatás" gomb is megmarad. Statisztika-csempék kattinthatók (szűrés), CVE-badge a hostsorban.
- **Kétnyelvű találatok:** a CVE- (`cvescan.py`) és kitettség- (`vulncheck.exposed_checks`) findingök `title`/`evidence` (HU) **és** `title_en`/`evidence_en` (EN) mezőt is hordoznak; a riport/UI a nyelvhez illőt mutatja (`report._fl`, `app.js fl()`). Régi (egynyelvű) findingök HU-ra esnek vissza → újraszkennelés kell az EN szöveghez.
- **CVE-motor** (`app/cvescan.py`, a CVE-fázis hívja): minden találat `method` mezővel, **külön reportolva**. **A) version** (Server/X-Powered-By): PHP php2shell (CVE-2026-109618/109619), PHP-CGI CVE-2024-4577 (Windows+CGI), Apache CVE-2021-41773/42013 (2.4.49/2.4.50), CVE-2021-40438 (≤2.4.48). **B) fingerprint** (kíméletes GET): Confluence verzió → CVE-2022-26134/22515. Verzió-alapú, NEM kihasználás. UI/PDF/MD két szekció; JSON `known_cves.by_version|by_fingerprint`. Appliance-ujjlenyomatok (Citrix/Ivanti/Fortinet/PAN/MOVEit) külön körben, advisory-ellenőrizve.
- Verzió: `app/__init__.py __version__` (most 0.9.3) + `/api/version` + lábléc; `app/BUILD` a deploy-szkriptből (gitignore). A HTML verziós asset-URL-lel megy (`?v=<verzió>`, a `/` route behelyettesíti a `__VER__`-t) + statikus `no-cache` → nincs beragadt régi app.js.
- Bemenet: `_norm_target` (main.py) felismeri: domain | IP | CIDR | `a-b`/`a.b.c.d-N` tartomány. IP-módban `engine.run_passive_ips()` leltároz (PTR + ASN/ország/org), nincs CT/wildcard/posture/takeover/brute; `opts.target_kind="ip"`, `target_ips` capelve `RECON_MAX_HOSTS`-ra.
- **XLS/CSV import (v0.8.0–0.8.1):** „Domain/IP betöltés (XLS/CSV)" gomb → fájl nyers POST-ként (`/api/import?name=…`, nincs multipart-függőség; a middleware `IMPORT_MAX`-ig enged). `_xlsx_cells`/`_csv_cells` kiolvassa a cellákat. `_parse_targets` → IP/CIDR/tartomány → **szkennelhető** IP-lista (`engine.scannable(ip, allow_private)`); `_parse_domains` → érvényes domainek (`_domain_or_none`, ami nem IP). `/api/import` visszaadja: `{ips, domains, count, domain_count, …}`.
  - **IP-lista:** `/api/scan {ips, source}` → `target_kind=ip` (IP-leltár).
  - **Domain-lista (v0.8.1):** `/api/scan {hosts:[…], ips:[…], source}` → `target_kind=hostlist` → `engine.run_passive_hosts()`: minden domaint felold (A/AAAA, PTR/ASN), él/nem él; a megadott IP-ket is beveszi ip-hostként. NINCS CT-enumeráció / wildcard / posture / takeover / brute. A **CVE** és **aktív** fázis ráhúzható (a hostokon működik), **teljes passzív** pedig domainenként külön indítható (host-részletben „Teljes passzív" gomb → `startScanFor` → sima domain-scan). Capelve `RECON_MAX_HOSTS`.
  - **Aldomén-felderítés fázis (v0.8.2–0.8.3):** domain-leltárnál külön, jól látható kártya („Aldomén-felderítés", a CVE/aktív mellé) → `POST /api/scan/{id}/subdomains` → `engine.run_subdomains()`: a betöltött domainekre CT-alapú felderítés (`sources.gather` + wildcard, **domainenként párhuzamosan, max 8**; nincs külön wait_for, a források eleve időkorlátosak – a 30s wait_for 0 találatot adott a lassú crt.sh-ra), az ÚJ hostok feloldva/gazdagítva a leltárhoz adódnak. Az új hostok `from_sub=True` (az `_resolve_all(extra=…)` az `info`-ba teszi, hogy az `_enrich` visszaíráson is átmenjen). Külön állapot `sub_status/sub_stage/sub_done/sub_total` (db-migráció); `sub_done` = ténylegesen hozzáadott hostok (+N). UI: a gombon „+N", az új hostokon `subtag` badge, külön „Aldomén" szűrő (`liveFilter==="sub"`). A CVE/aktív a sub alatt és után is indítható (státusz „done" marad, nincs 409). Capelve `RECON_MAX_HOSTS`. Workflow: import → gyors leltár (+CVE) → aldomén-felderítés / per domain teljes passzív / aktív.
- **Cég → IP-tartományok (RIR/BGP, v0.9.0):** `app/orgip.py` + `GET /api/orgip?q=…` → `orgip.discover()`: a `q` lehet **cégnév**, **ASN** (`AS…`) vagy **domain**. Források (GET-only, hibatűrő, best-effort): **RIPE DB REST** (org-keresés névre → ORG-handle; inverz inetnum/inet6num→CIDR + aut-num), **RIPEstat** (ASN→meghirdetett BGP-prefixek, GLOBÁLIS bármely RIR; AS-holder), **ARIN REST** (org+nets), **PeeringDB** (org→ASN), **domain-seed** (DNS→IP→ASN a Team Cymru enrichből). Kimenet `{orgs, asns, prefixes[{prefix,source,netname,cc,descr}], notes}` – review-hoz, forrás/netname/ország jelölve (WHOIS elavulhat). UI: a kereső-kártya alatt lenyíló „Cég → IP-tartományok" panel (`#orgipwrap`): keresés → checkboxos prefixlista + „mind ki/be" → **„Kiválasztottak → IP-leltár"** → `startScan {ips: kiválasztott CIDR-ek, source}` → a meglévő IP-leltár (`_parse_targets` bontja a CIDR-eket, cap `RECON_MAX_HOSTS`). Nem kihasználás. Globális ASN-út: pl. `AS15169` → ~1438 prefix. Átvíve a Brand Radarba is (v0.5.0).
  - **Több-seed + ASN→org (v0.9.1):** a `q` vesszővel/pontosvesszővel több seedet is tartalmazhat (cégnév + domain + ASN együtt), és a `discover()` minden felbukkant ASN-re lekéri a birtokló RIPE org-ot (`asn_org`) → annak inetnumait is behozza. **Miért kell:** az infrastruktúra gyakran külön cég/ASN alatt van — pl. a Yettel külső scope-ja a **CETIN** (ORG-CHZ1 / **AS8448**) alatt, a CETIN-inetnumokon `org:` sincs. Csak a „Yettel" névre keresve ezek kimaradnak; a **domain-seed** (`yettel.hu` → AS8448) hozza be őket. Ezért a legteljesebb lefedettséghez a cégnevet ÉS a fő domaint együtt kell megadni (`Yettel Hungary, yettel.hu` → a 2026Q2 scope mind a 63 IP-je lefedve). A UI-szöveg ezt javasolja.
- **Cégcsoportos workspace-ek (kapu + izoláció):** külön WIP, a `feat-workspaces` ágon (origin), még NINCS a main-ben. Közös cég-belépő titok + per-user `recon_ws` izoláció, invite-only linkek. A 2. fázis (infra: passkey le, `RECON_ACCESS_SECRET`/`RECON_WORKSPACES`) külön kiadás lesz.
  - **Pool-jelleg osztályozás (v0.10.2):** a prefix-rekord két új mezőt kap: `status` (RIPE inetnum/inet6num státusz) és `kind` (jelleg). A `kind`-et az `orgip._classify(netname, status)` számítja: a netname-mintából `dynamic`/`fixed`, a státuszból `allocation` (ALLOCATED*) / `aggregate` (AGGREGATED-BY-LIR) / `assigned` (ASSIGNED*), különben `unknown`. A netname-minták **konfigurálhatók**: `RECON_POOL_PATTERNS` env = JSON-lista `[["regex","dynamic|fixed"], …]`, ami a beépített minták elé kerül (alap: `-dynamic-/-dsl-/-pool/-mobile/-cgn/…` → dynamic; `-fixed/-static/-biz/-corp/…` → fixed). A BGP-ből jövő (netname nélküli) prefixeket a `discover()` dedup előtt összefésüli az azonos prefixű RIPE-rekord netname/status mezőivel, így a meghirdetett blokk is kap jelleget. **Cél:** a drága port-/szolgáltatás-szkennelést a fix/kiosztott tartományokra fókuszálni, a nagy dinamikus poolok helyett. UI (`app.js renderOrgResult`): soronként színes jelleg-címke (`.tag.fix/.tag.dyn/.tag.alloc`), `Mind/Fix/Dinamikus/Szülő` szűrő-pill, és **alapból csak a fix/kiosztott/ismeretlen van bejelölve** (dinamikus/szülő nem). A lista fölött állandó **caveat**: a jelleg registry-jelzés, NEM bizonyít mobilt/lakosságit/üzletit/CGNAT-ot. **750-cap aránykiírás:** az `/api/orgip` visszaadja a `scan_cap`-et (`RECON_MAX_HOSTS`), a UI kiírja „kiválasztva / szkennelhető" arányt (figyelmeztető szín, ha a kiválasztott IP-szám > cap — egy nagy /16 bejelölésekor csak az első cap IP kerül a leltárba). Nincs DB-migráció, a `kind` csak az orgip-válaszban él. A netname-konvenció operátoronként eltér, ezért a minta csak jelzés, nem szűrőfeltétel. A „Bontás" (`-M` /24-enkénti lekérdezés) külön, későbbi lépés lehet. A Brand Radar átvett kódja külön tükör — ott külön döntés.

## Döntések
- Csak engedélyezett célpontra (UI/README/LICENSE kiemeli). TCP-connect scan, nincs NET_RAW/ICMP.
- Egy IP-t egyszer szkennel (sok aldomén közös IP-n), de a HTTP-ujjlenyomat hostonként (vhost-aware); a hoston belüli ujjlenyomat korlátozottan párhuzamos (különben a polite túl lassú).
- „Kitett” csak `exposed_flags`/`vuln` alapján (`isExposed()`) – a nyitott 22/SSH önmagában nem kitettség (felhasználói visszajelzés).
- Ha a passzív fázis alig talál (≤1 host vagy 0 élő: wildcard cert / nincs apex A-rekord) → az aktív kártya jelzi és előre bepipálja a DNS-brute-ot (kliensoldali heurisztika).
- PQ-TLS: kézzel épített TLS 1.3 ClientHello üres key_share-rel, hibrid ML-KEM csoportokat kínál; HRR a PQ csoporttal = PQ kulcscsere. Nincs PQC-lib (a pqcheck technikája). Cert: stdlib DER-parse (RSA/ECDSA/EdDSA klasszikus, ML-DSA/SPHINCS+ PQ). MD+JSON exportban is.
- Exportok hostonként tagolva (figyelmet igénylő → élő → nem élő). XLSX: host×port soronként, host-mező minden sorban (a sávozás miatt), HTTP-státusz színkód, fagyasztás+szűrő; de-brandelt paletta (#0E2733 fejléc, #0B8FA0 akcent) – nem céges színek.
- Biztonság (AUDIT.md): CSV-képletinjekció (`_csv_safe`), SSRF (loopback/link-local/169.254 soha), `RECON_MAX_HOSTS=750`, `RECON_MAX_SOCKETS=512`, domain-hosszkorlát (ReDoS), SQL oszlopnév-fehérlista, `RECON_PROXY_SECRET` (`X-Recon-Proxy`) mélységi védelem, `RECON_ALLOWED_HOSTS`. CSP `style-src 'self' 'unsafe-inline'` (dinamikus sávok).
